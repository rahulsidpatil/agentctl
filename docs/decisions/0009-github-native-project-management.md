# 0009 — GitHub-native project management

- Status: Accepted
- Date: 2026-09-28

## Context

The public product needs transparent planning without adding a separate system
that contributors or agents must synchronize.

## Decision

Use GitHub Issues for work, parent/sub-issues for hierarchy, dependencies for
blocking, milestones for outcomes, and one public GitHub Project for workflow.

## Consequences

Repository templates and automation become reusable framework assets. The
personal-account repository uses labels because configurable issue types are an
organization-level capability.

## Revisit when

Scale, portfolio coordination, or compliance requires an additional system.
